# Teórica 09

**¿Cuándo conviene `TreeMap` en vez de `HashMap`? ¿Qué se gana y qué se paga?**

`TreeMap` conviene cuando se necesita algo que el hashing, por construcción, no da: **orden**. Concretamente: recorrer las claves **ordenadas**, consultas por **rango** (`subMap`: "todos los legajos entre 1000 y 2000"), el mínimo/máximo (`firstKey`/`lastKey`), o "la clave más cercana a X" (`floorKey`/`ceilingKey`).

Se gana el orden total de las claves y esas consultas; se paga que **todas** las operaciones pasan de $O(1)$ promedio a **$O(\log n)$** (por dentro es un árbol balanceado — próxima unidad), y que las claves deben ser comparables. Regla práctica: `HashMap` por defecto; `TreeMap` sólo cuando el orden o los rangos son parte del problema; `LinkedHashMap` si sólo hace falta recordar el orden de inserción.
