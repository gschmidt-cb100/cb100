# Teórica 02

**Armá la tabla de costos de ArrayList, ArrayDeque, HashSet/HashMap, TreeSet/TreeMap y PriorityQueue para buscar, insertar y borrar. ¿De qué unidad sale cada costo?**

| Estructura | Buscar | Insertar | Borrar | De dónde sale |
|---|---|---|---|---|
| `ArrayList` | contains O(n); get(i) O(1) | O(1) amortizado al final | O(n) (corrimiento) | U2 (arreglo que crece, amortizado) y U5 |
| `ArrayDeque` | O(n) | O(1) en ambas puntas | O(1) en ambas puntas | U5 (pila y cola sobre arreglo circular) |
| `HashSet` / `HashMap` | O(1) promedio | O(1) promedio | O(1) promedio | U7 (tabla de hash: función + resolución de colisiones + rehash) |
| `TreeSet` / `TreeMap` | O(log n) | O(log n) | O(log n) | U8 (árbol autobalanceado: la altura se mantiene logarítmica) |
| `PriorityQueue` | O(n) (búsqueda arbitraria) | O(log n) (flotar) | O(log n) el mínimo (hundir) | U9 (heap binario sobre arreglo) |

Tres letras chicas que valen nota: el O(1) del hash es **promedio** — depende de una buena función de hash y del factor de carga (U7); el O(1) del `ArrayList` al final es **amortizado** — la redimensión ocasional O(n) se prorratea (U2); y la `PriorityQueue` sólo es barata para SU operación estrella (el mínimo) — buscar un elemento cualquiera es O(n), por eso Dijkstra usa eliminación perezosa en vez de buscar y actualizar (U11).
