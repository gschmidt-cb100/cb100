# Teórica 08

**¿Qué relación hay entre el contrato `equals`/`hashCode` y el funcionamiento de un `HashMap`?**

El `HashMap` usa las dos operaciones en cascada: el **`hashCode`** de la clave decide **en qué balde** guardar/buscar, y el **`equals`** confirma la igualdad **dentro** del balde. Para que eso funcione se necesita el contrato: **si dos claves son `equals`, deben tener el mismo `hashCode`**. Si el contrato se rompe (por ejemplo, se redefine `equals` sin `hashCode`), dos claves "iguales" caen en baldes distintos: se guarda por un balde y se busca por otro, y el mapa "pierde" objetos — `contains`/`get` devuelven `false`/`null` con el objeto adentro.

Además las claves deben ser **inmutables**: si se muta una clave ya guardada, su `hashCode` cambia, pero el par quedó archivado en el balde del hash viejo — inhallable para siempre.
