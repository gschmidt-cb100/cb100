# Teórica 09

**¿Por qué iterar una `PriorityQueue` no da los elementos ordenados?**

Porque por dentro es un heap binario, y el heap sólo garantiza que **la raíz** es el mínimo: el resto del arreglo está "casi desordenado" a propósito (no hay orden entre hermanos ni entre subárboles). El iterador de `PriorityQueue` recorre ese arreglo interno **en el orden en que está**, así que `[1, 2, 4, 5, 3]` es una salida perfectamente válida — y lo mismo vale para `toString()` y para los streams sobre la cola.

Para consumir en orden hay que **desencolar**: `poll()` en un bucle (cada extracción re-acomoda el heap y expone al siguiente mínimo). Si lo que se necesita es una colección siempre ordenada y recorrible, la estructura correcta es otra: `TreeSet`/`TreeMap` (Unidad 8).
