# Teórica 05

**¿Qué es una lambda y qué una referencia a método? Dá tres ejemplos equivalentes lambda ↔ referencia.**

Una **lambda** es una función anónima escrita en el lugar donde se usa: parámetros, flecha, cuerpo — `alumno -> alumno.nota() >= 6`. Java la convierte en una implementación del "functional interface" que el método espera (`Predicate`, `Function`, `Comparator`…). Es la pieza que hizo posibles los streams: pasar COMPORTAMIENTO como argumento, no sólo datos.

Una **referencia a método** es la abreviatura para la lambda que no hace nada más que llamar a un método existente: se escribe `Clase::metodo` y el compilador deduce cómo conectar los argumentos.

Tres equivalencias típicas:

1. `alumno -> alumno.nombre()` ↔ `Alumno::nombre` — llamar un método de instancia del elemento (la más común en `map`).
2. `texto -> Integer.parseInt(texto)` ↔ `Integer::parseInt` — llamar un método estático con el elemento como argumento.
3. `(a, b) -> Integer.sum(a, b)` ↔ `Integer::sum` — método de dos argumentos, típico en `reduce`.

¿Cuál usar? La referencia cuando existe el método con nombre — se lee mejor (`.map(Alumno::nombre)` es casi castellano). La lambda cuando hay lógica propia (`a -> a.nota() >= 6`). Y cuando la lambda pasa de una línea o necesita llaves, suele ser la señal de que merece ser un método privado con nombre… y volver a la referencia.
