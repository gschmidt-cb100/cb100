# Teórica 07

**¿Qué hace `Collectors.groupingBy`? ¿Qué estructura del curso construye por dentro y cómo se personaliza el "qué acumular"?**

`groupingBy` es la terminal de clasificación: recorre el stream, le aplica a cada elemento una **función clasificadora** (la clave del grupo) y arma un `Map` grupo → elementos. `ventas.stream().collect(groupingBy(Venta::vendedor))` devuelve `Map<String, List<Venta>>`: cada vendedor con su lista.

Por dentro construye exactamente la estructura de la U7: un **`HashMap`** donde cada clave nueva crea su entrada y cada elemento se acumula en la de su grupo — el mismo patrón del contador de palabras (`merge`), industrializado. Con un segundo argumento se elige otra fábrica de mapa: `groupingBy(Venta::vendedor, TreeMap::new, ...)` da los grupos ordenados por clave (U8).

El "qué acumular" se personaliza con el **collector aguas abajo** (downstream), tercer parámetro:

- `groupingBy(Venta::vendedor, counting())` → cuántas ventas por vendedor.
- `groupingBy(Venta::vendedor, summingInt(Venta::monto))` → total facturado por vendedor (el `totalPorVendedor` del apunte).
- `groupingBy(Venta::vendedor, mapping(Venta::producto, toSet()))` → qué productos vendió cada uno.
- Y se anida: `groupingBy(Venta::vendedor, groupingBy(Venta::producto, summingInt(Venta::monto)))` → la matriz vendedor × producto.

La lectura profesional: `groupingBy` es el `GROUP BY` de SQL traído al lenguaje — y entenderlo por dentro (un mapa acumulando por clave, U7) es lo que te deja predecir su costo: O(n) con hash, O(n log g) con TreeMap.
