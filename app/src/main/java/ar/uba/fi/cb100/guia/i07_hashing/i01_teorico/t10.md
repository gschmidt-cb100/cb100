# Teórica 10

**¿Por qué no hay que comparar claves `Integer` con `==`? ¿Qué es el caché de boxing?**

Porque `Integer` es un **objeto**, y `==` entre objetos compara **identidad** (¿son el mismo objeto?), no contenido (Unidad 2). Dos `Integer` de valor 1000 creados por separado son objetos distintos: `a == b` da `false` aunque valgan lo mismo; lo correcto es `a.equals(b)`.

El **caché de boxing** hace el error especialmente traicionero: Java **pre-crea y reutiliza** los `Integer` de −128 a 127, así que en ese rango el autoboxing devuelve siempre el mismo objeto y `==` da `true` **por casualidad**. Resultado: el código "funciona" en las pruebas con números chicos y falla en producción con números grandes — el peor tipo de bug. Los `HashMap`/`HashSet` internamente comparan con `equals`, así que ellos no se equivocan; el riesgo está en el código propio que compara claves o valores con `==`.
